# Beitrag über die Weboberfläche vorbereiten

Die Weboberfläche verarbeitet Textdateien nur lokal im Browser. Verwende ausschließlich synthetische, selbst erstellte oder öffentlich nutzbare Inhalte mit geklärter Lizenz.

1. Wähle den Artefakttyp und fülle die Fragen in Alltagssprache aus.
2. Übernimm bei Bedarf `.md`, `.txt`, `.yml`, `.yaml` oder `.json` lokal in ein Feld. PDF/DOCX bleiben lokale ZIP-Anhänge.
3. Vervollständige Szenarien, Quellen, Lizenz und die drei Selbstauskünfte.
4. Behebe alle Fehler in „Prüfung & Vorschau“. Hinweise auf mögliche PII müssen bewusst geprüft werden.
5. Wähle einen Einreichweg:
   - **GitHub-Issue:** nur für reine Textbeiträge. Der übergebene Text ist im öffentlichen Issue und späteren Pull Request sichtbar. Ein Maintainer setzt das Import-Label.
   - **ZIP:** enthält das vollständige Paket einschließlich PDF/DOCX. Forke anschließend das Repository, lege einen Branch an, lade die Dateien hoch und öffne einen Pull Request.

Die technische Prüfung ist keine fachliche, rechtliche oder Trust-Freigabe. Diese erfolgt im Pull Request durch Menschen.
